# Decisions

## 2026-08-11 — 학습 UX를 개념 이해 60% + 시각적 실행 피드백 40%로 구성

- 결정: Python Future Lab의 핵심 학습 UX는 **Codédex식 개념 이해 구조 60% + CodeCombat식 시각적 실행 피드백 40%**를 원칙으로 삼되 시각 요소와 문구는 독립적으로 설계한다.
- 핵심 학습 모델: **SEE → CONNECT → CHANGE → RUN → CODE**.
- 장기 목표: 학습 레벨이 올라갈수록 블록 의존도를 줄여 LEVEL 4에서 블록 없이 순수 Python 코드를 작성하게 한다.
- 첫 적용 범위: Mission 01 Step 1만 새 구조로 완성하고 Mission 02·03은 기존 UX를 유지한다.
- 기존 기능 보호: 인증·Supabase·RLS·진도·XP 데이터 계약은 변경하지 않고 표시 계층과 안전 검증 피드백만 확장한다.

## 2026-08-11 — 휴대폰 번호와 4자리 PIN을 서버 파생 인증으로 사용

- 휴대폰 번호는 SMS로 소유권을 확인하지 않고 서비스 내 고유 로그인 ID로만 사용한다.
- 사용자가 입력한 4자리 PIN은 Supabase에 그대로 보내지 않고 서버 전용 pepper와 HMAC-SHA256으로 긴 인증 문자열을 파생한다.
- 전화번호·IP별 실패 횟수, 5회 실패 잠금, 서버 전용 관리자 키로 짧은 PIN의 온라인 대입 위험을 완화한다.
- 비밀번호 분실 시 자동 SMS 복구가 없으므로 운영 전 별도 복구 정책이 필요하다.

## 2026-08-11 — Vercel 배포는 Next.js 네이티브 빌드를 사용

- 배경: 기존 기본 빌드는 Cloudflare Worker용 `dist`를 만들고 API가 `cloudflare:workers`에 의존해 Vercel Next.js 빌드가 실패했다.
- 결정: 기본 `dev/build/start`를 Next.js로 전환하고 `vercel.json`으로 프레임워크를 명시한다. Sites용 vinext 명령은 별도 스크립트로 보존한다.
- 영향: 데모 진도는 외부 DB 없이 서명 쿠키에 저장되므로 같은 브라우저에서만 이어진다. 운영용 다중 기기 계정은 별도 관리형 DB가 필요하다.

## 2026-08-04 — 데모 계정은 서버 세션과 D1을 사용

- 배경: 사용자가 이름 3글자와 PIN 4자리로 로그인하고 학습 기록을 이어가길 요청했다.
- 결정: 단일 데모 계정은 서버에서 검증하고 불투명 HttpOnly 세션을 발급하며, 진도와 코드는 D1에 저장한다.
- 이유: 브라우저 저장소보다 세션 간 지속성과 소유권 검증이 명확하고 실제 인증 전환 시 데이터 계층을 재사용할 수 있다.
- 제한: 공개 운영용 회원가입 시스템이 아니며 실제 학생 서비스 전에는 관리형 인증으로 교체한다.

## 2026-08-04 — 첫 화면 비주얼을 코드 기반 모션그래픽으로 구현

- 배경: 정적 이미지 삽입이 아니라 영상처럼 생동감 있는 첫 화면이 필요했다.
- 대안: MP4/WebM 배경 영상, Canvas/WebGL 장면, HTML/CSS/React 애니메이션.
- 결정: HTML/CSS/React 애니메이션을 사용한다.
- 이유: 별도 미디어 다운로드 없이 빠르게 로드되고, 텍스트·버튼 접근성을 유지하며, 반응형과 모션 축소 설정을 정교하게 제어할 수 있다.
- 영향: 사진 수준의 사실감보다 선명한 제품 UI와 상호작용 일관성을 우선한다.

## 2026-08-04 — 첫 MVP에서 Python을 실행하지 않음

- 배경: 첫 미션은 반복 횟수 하나만 검증하면 되며 임의 코드 실행은 위험과 운영비가 크다.
- 대안: 서버 프로세스 실행, 브라우저 Python 런타임, 제한 문법 해석.
- 결정: 제한 문법 해석을 선택한다.
- 영향: 안전하고 빠르며 테스트 가능하다. 자유 코딩은 샌드박스 도입 전까지 지원하지 않는다.

## 2026-08-04 — 빈 저장소에 Sites vinext 기반 구성

- 배경: 프로젝트가 비어 있고 배포 가능한 반응형 웹 기반이 필요했다.
- 결정: Next.js App Router 호환 API와 Cloudflare Worker 호환 빌드를 제공하는 starter를 사용한다.
- 영향: 로컬 구조는 표준 React/TypeScript로 유지하고, Supabase는 어댑터로 후속 연결한다.
