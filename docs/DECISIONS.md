# Decisions

## 2026-08-04 — 데모 계정은 서버 세션과 D1을 사용

- 배경: 사용자가 이름 3글자와 PIN 4자리로 로그인하고 학습 기록을 이어가길 요청했다.
- 결정: 단일 데모 계정은 서버에서 검증하고 불투명 HttpOnly 세션을 발급하며, 진도와 코드는 D1에 저장한다.
- 이유: 브라우저 저장소보다 세션 간 지속성과 소유권 검증이 명확하고 실제 인증 전환 시 데이터 계층을 재사용할 수 있다.
- 제한: 공개 운영용 회원가입 시스템이 아니며 실제 학생 서비스 전에는 관리형 인증으로 교체한다.

## 2026-08-04 — 첫 화면 비주얼을 코드 기반 모션그래픽으로 구현

- 배경: 정적 이미지 삽입이 아니라 영상처럼 생동감 있는 첫 화면이 필요했다.
- 대안: MP4/WebM 배경 영상, Canvas/WebGL 장면, HTML/CSS/React 애니메이션.
- 결정: HTML/CSS/React 애니메이션을 사용한다.
- 이유: 별도 미디어 다운로드 없이 빠르게 로드되고, 텍스트·버튼 접근성을 유지하며, 반응형과 모션 축소 설정을 정교하게 제어할 수 있다.
- 영향: 사진 수준의 사실감보다 선명한 제품 UI와 상호작용 일관성을 우선한다.

## 2026-08-04 — 첫 MVP에서 Python을 실행하지 않음

- 배경: 첫 미션은 반복 횟수 하나만 검증하면 되며 임의 코드 실행은 위험과 운영비가 크다.
- 대안: 서버 프로세스 실행, 브라우저 Python 런타임, 제한 문법 해석.
- 결정: 제한 문법 해석을 선택한다.
- 영향: 안전하고 빠르며 테스트 가능하다. 자유 코딩은 샌드박스 도입 전까지 지원하지 않는다.

## 2026-08-04 — 빈 저장소에 Sites vinext 기반 구성

- 배경: 프로젝트가 비어 있고 배포 가능한 반응형 웹 기반이 필요했다.
- 결정: Next.js App Router 호환 API와 Cloudflare Worker 호환 빌드를 제공하는 starter를 사용한다.
- 영향: 로컬 구조는 표준 React/TypeScript로 유지하고, Supabase는 어댑터로 후속 연결한다.
