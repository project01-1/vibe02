# Security

- 사용자 PIN은 휴대폰 번호와 서버 전용 `AUTH_PIN_PEPPER`를 HMAC-SHA256으로 결합한 뒤 Supabase Auth 비밀번호로 전달하며 평문을 저장하지 않는다.
- Supabase SSR 세션은 HttpOnly 쿠키를 사용한다.
- 휴대폰 번호는 SMS로 소유권을 확인하지 않은 서비스 내 고유 로그인 ID다.
- 회원가입·로그인은 전화번호·IP 조합별로 5회 실패 시 15분 잠근다.
- 학습 기록 API는 서버에서 코드를 재검증하고 사용자 ID나 완료 여부를 클라이언트 입력으로 받지 않는다.
- XP는 서비스 역할 전용 PostgreSQL RPC에서 최초 완료일 때만 지급한다.

- MVP는 학생 코드를 실행하지 않는다. Zod + 허용 정규식으로 `for … range(n): move()` 한 형태만 해석한다.
- 향후 실제 실행은 네트워크·파일시스템 차단, CPU/메모리/시간 제한, 패키지 allowlist, 무한 루프 방어를 갖춘 별도 샌드박스에서 처리한다.
- Supabase 적용 시 모든 사용자 데이터에 RLS를 활성화하고 서버에서 관리자 역할을 재검증한다.
- 민감정보·토큰·전체 코드는 로그에 남기지 않는다. 공개/서버 환경변수를 구분한다.
- 최소 개인정보: 서비스 로그인 ID인 휴대폰 번호와 표시 이름만 수집하며, 학교·생년월일은 기본 수집하지 않는다.

## 출시 체크리스트

- CSP·보안 헤더, rate limit, 인증 없는 쓰기 차단, 관리자 서버 검증.
- 개발/운영 데이터와 테스트/운영 계정 분리, 백업·복구 훈련.
- 의존성 라이선스·취약점 점검, 오류 메시지 내부정보 제거.
